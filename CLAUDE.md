# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install      # install dependencies
npm run dev       # start Vite dev server at http://localhost:3000 (auto-opens browser)
npm run build      # production build, output to build/
npm run server     # start the Express + SQLite API at http://localhost:3001 (tsx watch)
npm run dev:all    # run API and Vite dev server together
```

There is no lint, typecheck, or test script configured in `package.json`, and there is no `tsconfig.json` in the repo — the build (via `@vitejs/plugin-react-swc`) transpiles TypeScript without type-checking it, so `tsc` errors will not surface from `npm run build`.

## Architecture

This is a small single-page Vite + React 18 + TypeScript app (an "Interactive Treasure Box Game"). Entry point is `src/main.tsx`, which mounts `src/App.tsx` into `#root`.

- **All game logic and UI lives in `src/App.tsx`** as one component. Game state (`boxes`, `score`, `gameEnded`) is plain `useState`; there's no external state management or routing.
- **Players and scores**: `src/components/StartScreen.tsx` asks for a name (no password; an unknown name is created) or lets the player continue as a guest. `App.tsx` remembers the last name in `localStorage` and, when a round ends, saves the score for named players only via `src/api.ts`. Guest scores are never saved.
- **Backend (`server/`)**: a small Express API (`server/index.ts`, port 3001) backed by SQLite via `better-sqlite3` (`server/db.ts`, file `server/data/game.db`, gitignored). Tables: `users` (username is case-insensitive unique) and `scores` (one row per finished round). Vite proxies `/api` to it (`vite.config.ts`, `strictPort` keeps Vite off 3001).
- **Precompiled Tailwind caveat**: because `src/index.css` is prebuilt, a Tailwind class not already used somewhere in the original export has no CSS (e.g. `max-w-md`, `grid-cols-3`, `mt-8`). Grep `src/index.css` before relying on a new utility class; fall back to inline `style` when missing.
- **`src/components/ui/`** is a full shadcn/Radix-based UI component library (button, dialog, form, sidebar, etc.). Most of it is unused scaffolding — `App.tsx` currently only imports `Button` from it. Treat it as available building blocks rather than active app structure.
- **`src/components/figma/ImageWithFallback.tsx`** is a helper originating from Figma Make/shadcn-exported designs, used for images with fallback handling.
- **Path alias**: `@` resolves to `src/` (configured in `vite.config.ts`).
- **Versioned import aliases in `vite.config.ts`**: many entries in `resolve.alias` map versioned bare specifiers (e.g. `"lucide-react@0.487.0"`) to their plain package names (e.g. `"lucide-react"`). This exists because the `src/components/ui/*` files (generated by Figma Make/shadcn export tooling) import packages using version-suffixed specifiers directly in `import` statements. If you add/upgrade a dependency that a UI component imports this way, update the corresponding alias in `vite.config.ts` rather than editing the import strings in every component file — or vice versa, keep both in sync.
- **Styling**: Tailwind CSS v4. `src/index.css` (imported by `main.tsx`) is a large, pre-compiled Tailwind CSS output file committed directly to the repo — there is no `tailwind.config` or PostCSS config, so Tailwind is not being (re)generated at build time. `src/styles/globals.css` defines the design-token CSS custom properties (colors, radii, etc.) but is **not currently imported anywhere** — it's a reference/leftover from the design export, not live styling.
- **Assets**: images in `src/assets/`, audio in `src/audios/`, imported directly into components as ES module imports (handled by Vite's asset pipeline).
- **`src/guidelines/Guidelines.md`** is an empty template (no project-specific guidelines have been filled in).
